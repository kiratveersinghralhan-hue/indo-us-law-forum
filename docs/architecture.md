# Frontend architecture — provisional

## Stack and routing

React, Vite, strict TypeScript and Tailwind via its Vite plugin. `src/router.tsx` centralizes route registration, history/hash mode and basename using React Router data routers. The maintained `useBlocker` handles unsaved internal/back navigation; it is not an authentication or authorization guard. Admin UI is lazy-loaded. `src/config/navigation.ts` provides links and slug helpers. Vite's build base is separately explicit in `vite.config.ts`.

## Components and state

`Layout` owns the prototype banner, header, disclosure-style mobile navigation, skip link, route focus/scroll handling and footer. Escape closes mobile navigation and returns focus to its toggle. Shared buttons, links, labels, inputs, selects and textareas live in `components/ui.tsx`, together with loading, empty, error and not-found views. `StructuredContent` renders a discriminated union of text blocks; no HTML injection. Article cards, case rows and procedural research artwork are reusable components.

Content loading uses `useResource`: async loaders, retry and stale-response suppression on filter changes/unmount. Provider failure produces an error view. Root rendering failures have an error boundary. Route content is remounted by pathname for reliable animation cleanup; query changes preserve filter focus. GSAP reveal observes newly inserted content groups and cleans its triggers, context, observer and owned styles on mode or route changes. Explicit Full homepage groups use bounded fade-and-rise/image reveals; replay occurs only after completely leaving and re-entering the viewport. Opacity never reaches zero. Other public pages retain the small existing translation, keeping article reading calm. Reduced removes all reveal transforms/opacity.

`ResearchCarousel` consumes provider-returned Article models and owns one selected index across presentation changes. In explicit Full with CSS perspective/preserve-3d support, `article-orbit.ts` owns the rotor transform, container resize, transient GSAP snap/entry tweens and horizontal pointer intent. Drag writes are coalesced with one pending RAF; selection updates React once after the gesture, never per animation frame. Gestures are bounded to ±360° and snap to an article. Normal touch scrolling/pinch is preserved with `touch-action: pan-y pinch-zoom`; capture starts only after horizontal intent. A bubbled implicit capture loss from a touch child is distinguished from losing the stage's capture.

The orbit's three original artwork covers are decorative/aria-hidden with no moving focus targets. Title, abstract and working link remain in a stationary readable panel. Focusable stage keys and separate prev/next/dot controls reach every article; selection alone updates the polite slide-position announcement. Full controls cycle through 360°. A brief entry orientation cue settles without changing selection or starting autoplay. A local error boundary retains the conventional presentation if initialization fails.

Reduced mode, System and unsupported CSS 3D retain the native overflow/scroll-snap carousel. Buttons/dots and viewport keys operate its scroll position; index changes are guarded against redundant React updates. Reduced uses immediate scroll. `EditorialArtwork` reads the central registry and reserves aspect-ratio space; `TeamCard` retains neutral original avatar art. No second carousel/WebGL renderer, external models or new scroll library was added.

Replaceable brand/copy/assets and mock content are centralized in `config/brand.ts`, `config/site-copy.ts`, `config/media.ts` and `data/mock-data.ts`. The content checklist maps individual fixtures and shared visuals to required client material. UI labels/validation remain with their components. There is no content-hiding production flag.

## Data boundary

Small `ArticleProvider`, `CaseProvider` and `DirectoryProvider` interfaces combine into the read-only `ContentProvider`. Public pages receive only published public models; admin-only IDs/status/conversion fields are not exposed in article/case projections. `getSiteSettings` reads the current cached copy, while record reads are asynchronous. `AdminProvider` is a separate typed mutation interface with snapshot reads, validated CRUD, review/conversion, ordering, settings and reset. Components import neither fixtures nor localStorage. `src/main.tsx` selects an explicit environment; mock mode constructs local-demo providers and configured backend mode uses a separate Supabase provider. Production failure must never become a mock fallback.

`admin/seed.ts` assembles fictional defaults from `data/mock-data.ts` and `data/site-settings.ts`. `data/mock-provider.ts` retains the isolated read-only baseline used by focused tests/fixtures. The shared demo environment caches validated records, emits revisions through `useSyncExternalStore`, and refreshes on the namespaced browser `storage` event. `DemoDataRoot` supplies a fresh public reader on revision, triggering normal public loaders. Settings reorder actual section DOM order, preserving existing markup and motion; the GSAP scope reinitializes on section-order/visibility changes.

Mutations re-read the namespace, validate a cloned snapshot, write it once and then notify. Failed storage writes do not report success or mutate the cached records. Existing corrupt/unreadable stores fail visibly; only explicit confirmed reset replaces them with defaults. Placeholder chrome can remain around an error, but record lists never silently return seed data. The 2 MB serialized limit protects this prototype from oversized local writes; it is not a production storage quota or security guarantee.

Fictional content lives only in `dilraj-editorial:local-admin-demo:v1`, separate from checked-in configuration and motion preferences. No credentials, real personal information, file contents or submissions entered on the public form are persisted. Public submission validation remains memory-only with no delivery/success confirmation. Local image preview URLs are revoked on replacement/unmount and never saved; supporting documents are text placeholders, not files. HTTP/HTTPS sample links reject embedded credentials and other URL schemes. Structured content permits paragraph, heading, list and note blocks only, rendered as escaped React text.

Conversion requires approval and stores a stable source-to-article ledger; repeated calls resolve the same draft. Removal of the draft leaves the conversion marker so a second draft cannot be created. No conversion auto-publishes. One browser's sequential edits and existing public tabs are supported; localStorage is not a database transaction or multi-user concurrency mechanism. Simultaneous cross-tab writes may overwrite edits. Future backend conversion needs uniqueness and atomic transitions. Open editors preserve their own unsaved state rather than silently merging external edits; reload to obtain another tab's changes.

Admin forms retain state through store refresh, expose validation/save/error/empty/loading states, require fictional-content confirmation and warn on dirty navigation/reload. Native confirmation dialogs isolate focus, start on Cancel, support Escape and restore focus. Reset clears the current editor as well as saved records; it leaves motion state intact. Accessible up/down controls cover collections, structured blocks, featured selections and existing homepage sections. Optional visibility applies only to deliberate existing sections, not a blanket switch to conceal missing production content.

## Supabase implementation — prepared, unapplied, security unverified

`VITE_DATA_MODE=mock|supabase` selects the environment in `main.tsx`. Missing/invalid backend configuration fails visibly and never imports seeds. `backend/provider.ts` implements the existing public/admin interfaces; `backend/contracts.ts` adds staff session, catalog and upload capabilities without moving reads into components. Browser-local mutations retain their isolated fictional namespace. `DemoDataRoot` remains the shared provider root for both environments; its historical name does not imply backend fallback. Public settings loading errors are explicit; the provisional shell can remain visible, but lists never substitute sample records.

Admin login/recovery routes are centralized. `StaffGate` is a navigation aid; current database staff lookup and RLS enforce authorization. SDK auth callbacks defer database requests to avoid callback lock contention. Accounts, authors and team profiles are separate. Limited Tiptap content is serialized to the existing paragraph/heading/list/note union and rendered as escaped React text, with no unsafe HTML. Existing mock editor and workflow labels remain available in mock mode.

Prepared migrations include relational category/author/asset references, publication columns and bounded JSON editorial data, provisional case metadata, private submission/attachment records, homepage/settings and operation activity. Articles/cases/team use optimistic revision checks. Review/conversion and ordering/settings operations use narrow transactional RPCs; conversion locks the source and preserves its once-only marker after draft deletion. No staff-provisioning browser function exists. All buckets are private; public editorial/document reads require a published reference. Intake is gated off independently in both server environment and private database configuration.

See [backend setup/security evidence](backend-setup.md), [content intake/import](client-content-intake.md) and [hosting strategy](hosting-seo-strategy.md). Docker/Podman absence prevents executing migrations, PL/pgSQL, Auth/RLS/Storage/Edge tests. These implementations require local full-stack verification and a separately authorized dedicated-project setup before launch. Analytics are isolated and disconnected.

## Isolated 3D and motion enhancement

`HeroArtwork` reserves a responsive stage and renders `SculptureStatic` immediately. Every viewport mounts the lazy `WebGLScene`, including reduced-motion visitors. A local boundary contains chunk/render errors. `sculpture-engine.ts` owns Three.js resources and returns an idempotent disposal function to the React effect. It uses procedural panels, a charcoal spine and a copper ring, soft lights, fine-pointer rotation and small independent panel float. GSAP ScrollTrigger controls limited depth movement on both touch and desktop; normal scrolling is preserved. Runtime drawing errors, context loss and initialization failure remove the canvas and expose the static composition. A GSAP enhancement failure is isolated from WebGL initialization.

The shared motion context exposes System / Reduced / Full. A new visitor begins Reduced with the optional accessible welcome; only explicit choices persist. Dismissal is session-only. The old automatically stored System default is migrated to the welcome, while old Full/Reduced selections are retained. New explicit System selections are marked and remembered. System follows the reactive OS setting; Reduced always disables motion; Full is an explicit stored visitor override authorized in the current public pass. It is never selected automatically. The preference is validated and storage failures fall back safely. Mode changes reconfigure the scene as animated or still and revert/recreate GSAP effects immediately. CSS checks the same effective mode, so OS media rules do not accidentally suppress explicit Full. `useEditorialMotion` owns a separate orbit-camera transform for bounded scroll framing, conventional artwork parallax, desktop repository artwork framing and fine-pointer supporting-card tilt. The orbit rotor has a different transform owner, preventing angle/scroll conflicts. Pointer geometry is cached and invalidated on resize/native scroll. Reveals scan only newly added groups, avoiding whole-page scans when carousel text changes. The repository's CSS sticky introduction has a bounded parent and releases normally; at 1080px and below it uses static flow. Scroll effects run at all widths with smaller mobile/tablet distances; touch events never drive tilt. Media contexts and custom listeners are cleaned on route changes. The entrance reveal uses the placeholder label, never obscures content and is configurable. `motion.ts` contains amplitudes, responsive pixel ratios, frame caps and camera settings; colors come from CSS tokens.

Intersection and document visibility checks stop rendering. Frame pacing advances a stable budget with fractional-RAF tolerance instead of discarding each frame remainder; compact scenes cap at 30 fps and desktop at 60 fps. Renderer size/DPR changes are guarded, avoiding repeated reallocations when resize sources report the same dimensions. Orbit tweens also pause offscreen/hidden and dispose on mode/route changes. Reduced mode draws initially and only when invalidated by resizing; it has no recurring frame request. ResizeObserver and a window resize listener fit the rotated geometry bounds to both container dimensions, including orientation changes. Small devices use shared geometry, a lower-detail ring, fewer drawn rules and lower DPR/frame caps. Renderer antialiasing is retained so thin rules stay smooth at DPR 1. No shadows, postprocessing or external media are required. The decorative canvas has `aria-hidden` and `tabIndex=-1`. SVG artwork is only for loading, chunk failure and GPU failure; neither width nor reduced motion is a fallback condition.

Lifecycle tests use real procedural geometry with a mocked WebGL renderer and GSAP tween. They verify framing, still-mode invalidation, failure recovery, pause/resume and cleanup, but do not measure GPU performance. Playwright tests load the regular `/` homepage and public routes in an isolated Chromium browser with viewport, touch and OS-motion emulation. System and Reduced respect reduction; Full tests select the actual product control explicitly. No fixture entry is needed. The older separate development HTML fixture remains excluded from the production build. All screenshots, videos and traces go to ignored `.qa/`.

## Welcome and session intro

The welcome uses a native modal dialog and starts Reduced. Full choice sets an exit phase without changing the global mode; a 300 ms exit completes before the preference updates, the dialog unmounts and focus is restored. Reduced choices/dismissal close immediately. The Full exit has its own small opacity/translate/scale transition so the default Reduced policy does not accidentally remove the requested transition. No body scroll lock is installed.

`EditorialIntroGate` mounts only on the homepage, after welcome closes and only for explicit Full. It reserves no document flow: a pointer-through visual layer gives fine lines/type a 1.35-second transition into the already-rendered hero. Only its Skip button receives pointer input. A timer ensures completion even if CSS/WebGL fails; Escape/Skip finish early. `editorial-intro-seen` in sessionStorage, with an in-memory fallback, prevents repeats across routes/reloads in the session. Reduced and route changes remove it; focus is restored only if the intro currently owns focus, preserving navigation access. Timers/listeners clean on unmount. Existing hero, sculpture and carousel remain independent.

## Hosting, GitHub Pages and SEO — unresolved

Local history routing is provisional. GitHub Pages does not inherently provide an SPA rewrite for clean deep links. Hash routing reduces deep-link hosting requirements but changes public URLs; a custom fallback still needs validation and does not solve article SEO by itself. Decide hosting, domain, project-path base and whether articles/cases need prerendering or SSR before release. Then align router mode/basename, Vite base, metadata, canonical URLs, sitemap, actual HTTP 404s and share previews. Keep the current prototype `noindex` until approved content is ready.
